# Project delivery requirements

- User requires every system update to reach the Android app as well as the website. The Android package is a TWA for https://quanlydakenh.vercel.app/; web changes normally need deployment to that origin, not a new APK. Native changes require a signed APK version bump using the existing private signing key.
- Before declaring deployment complete, verify the served frontend assets match the intended release, API health is good, and test the installed app where relevant. Read android-app/FRONTEND-DEPLOYMENT.md: Vercel static overrides must be updated together with the VPS checkout; a git push or VPS restart alone is not proof the app has the update.
- For layout changes, check phone (390px), unfolded touch (840px), landscape touch (1100px), and desktop mouse. Use scripts/test-fold-navigation.mjs. Review screenshots, chat selection, composer visibility, navigation dismissal and scrolling, horizontal overflow, and keyboard/viewport behavior when relevant. Keep native push receipt and conversation deep-link tests for notification changes.
- Do not claim physical Samsung Fold 7 testing based only on emulator or browser tests. Preserve unrelated user files. Keep keys, tokens, production screenshots/customer data out of Git.
- Automatic Vercel-GitHub linking was rejected by automatic approval review on 2026-10-23. Do not enable that persistent automatic production deployment without explicit user approval for linking the project and deploying every main commit. Existing manual deployment authorization remains separate.
