# Qualified customer directory — 2026-10-27

Scope: Settings > Customers (and the same customer table entry point). This filters the directory; it does not delete chat/comment identity records or conversation history.

Eligibility: phone/address, an existing order (including draft/history), a declared deposit, local plan/handoff, imported taophacdo origin or learner source facts. Email-only and chat/comment-only records are excluded. Qualified group members can additionally use an explicit learner status profile. Explicit qualified group representatives have priority; otherwise prefer a member with plan/status/contact/order evidence. Member matching is channel-bound. A representative appears once even if associated with multiple groups; unrelated group placeholders are excluded. A group's own qualified stored profile remains a fallback when there is no qualified member. The directory does not silently reassign chat/care ownership.

Implementation: GET /api/customers/directory returns 50 summary rows, total/page counts, accent-insensitive search and precomputed order totals. A 15-second per-user/role cache is bound to relevant record/permission revisions; writes invalidate it immediately through revisions. No remote Supabase request or full message scan is needed for the list. Settings keeps the compact settings shell instead of fetching the complete workspace. Browser requests are coalesced and stale searches/account changes cannot overwrite newer results. No private persistent browser cache is introduced.

View opens the existing full learner profile, including contact, status, plan/dates, attendance/security, common groups, purchases/order information and notes. Its phone/history lookup now queries relevant conversations using an SQLite index instead of deserializing all messages twice. Existing profile write/payment behavior is retained. Access to a selected group representative follows the assigned group's channel, including when a separate personal conversation has not been created.

Validation: directory eligibility/group/deduplication, role scoping, cache invalidation, search/page counts and indexed learner-message facts; existing learner profile/workflow/lookups suites: 25 tests pass. UI fixture with 4000 chat-only contacts and 53 eligible records renders 50 rows; first display measured 128–151 ms on localhost (not a production promise).
