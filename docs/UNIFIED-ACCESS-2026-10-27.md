# Unified permissions and accounts

Settings → Quyền/ tài khoản is now the account and role matrix for the hub and embedded plan manager. The old plan permission/account pages open this setting. Plan roles, permission names, mappings and admin email identities are imported once into the existing SQLite settings record (`unified-access-v1`), atomically; source Supabase role tables and Auth are not rewritten. Subsequent changes use this single local authority inside QLDaKenh. This does not change a separate standalone phacdo deployment.

Existing hub identities retain their IDs and credentials. Matching plan emails are linked without changing an existing hub role. Plan-only admin identities are listed as locked, waiting for an administrator to set a hub password; existing Supabase passwords cannot be copied. All source role/permission codes, including custom or orphaned mapping codes, are retained. Failed source reads never replace existing rights or report a successful import.

Rows show role defaults followed by assigned users. User booleans explicitly allow or deny a right independently of the role. Changing a role keeps personal overrides. Role rows require Edit, then Save/Cancel; user checkboxes save immediately and retain horizontal/vertical table scroll. User forms edit name, login email, role and optionally password. Delete deactivates and removes the user from the matrix while preserving processing history.

The owner role is protected against lockout, deletion, demotion and permission removal. Delegated permission managers cannot grant rights they do not hold, edit their own role, or change protected owner accounts. Mutations use the matrix version to reject stale concurrent edits. Locks, deletion and credential changes revoke affected sessions; normal permission edits take effect on the next request without unnecessarily logging the user out. Passwords use the hub's salted scrypt format and are never returned or audited.

Named hub menus and settings tabs are filtered by effective permission. Unlisted menus retain their existing behavior. API guards also enforce named areas, conversation kind and plan CRUD operations. Plan customer writes compare existing values so saving an unchanged email/status does not incorrectly require email or restoration privileges. The authenticated proxy denies non-owner access to auth/functions and unknown tables rather than exposing its privileged upstream credential.

The embedded plan app no longer forces every session to super_admin or uses localStorage role fallbacks. Only the hub owner receives that UI sentinel; other accounts use a per-user sentinel plus effective permissions. Rights are checked at most every 15 seconds and on focus, without refetching the heavy learner list when unchanged. Persistent learner caches are not hydrated across identities; the API cache remains authoritative. The browser's obsolete plaintext SSO password key is removed.

Validation: 23 affected model/security/snapshot tests, full create/edit/lock/delete account UI and role/override UI at 390/840/1100/1440 px, limited user plan rendering, direct API denial and session revocation. Fold navigation checks pass. Full suite: 1050/1054 passed; the same four failures reproduce with original backend files (conversation-tags-mentions, two copy-automation-loading cases and data-load-http).

Deployment requires the new VPS backend and Git-triggered Vercel static build, including plan-ui assets. Android is a TWA and receives the same web release on reload. No physical Samsung Fold test is claimed. Run scripts/diagnose-unified-access.mjs after updating the backend; it prints counts only, never identities or credentials.
